## 2026-08-03T19:11 — D — Active org = single httpOnly cookie
- **Decision:** `ledgerly_active_org` httpOnly cookie is the active-org source of truth; written only by server code (cookieStore); switching triggers full-page reload.
- **Prevents:** client cookie shadowing (root cause of the earlier `/expenses` "no active org" bug), stale per-org caches, org leakage between tabs.
- **Note:** Ratifies existing org-context/server-action pattern; FR-2 ensures earliest-`created_at` fallback when the cookie names an org the user left.

## 2026-08-03T19:11 — D — Server actions are the only mutation boundary
- **Decision:** All writes (roster, invites, plans, org settings, requests, audit) go through `'use server'` actions in `features/*/actions.ts`; client components never mutate directly.
- **Prevents:** client-side writes bypassing RLS/validation; drift between optimistic toasts and committed state.
- **Note:** Ratifies existing convention (docs/adrs/003); server actions revalidate affected routes via `revalidatePath`.

## 2026-08-03T19:11 — D — RLS is authoritative; app checks are defense-in-depth
- **Decision:** RLS (SECURITY DEFINER helper functions) is the data boundary; app-level role checks exist but never as the sole gate.
- **Prevents:** app-only gating patterns that fail open when a new route omits the check.
- **Note:** Ratifies existing `is_super_admin` / `is_org_member` / `can_write_in_org` helper family.

## 2026-08-03T19:11 — D — Org-admin boundary = new can_admin_org helper
- **Decision:** New SECURITY DEFINER `can_admin_org(org_id)` = `role = 'org_admin'` membership OR super-admin-of-that-org; roster/invite/request/plan mutations gate on it. `org_admin` is a plain `org_members.role` value; `super_admin` platform rows are OUTSIDE org-admin scope; `/admin` requires `role = 'super_admin'` only. Migration 013 closes `010_unify_org_member_write`'s uniform-write relaxation for admin surfaces.
- **Prevents:** any-member roster tampering / self-escalation (010:12), org_admin reaching `/admin`, org admin demoting platform staff.

## 2026-08-03T19:11 — D — Approval + join are atomic DB operations
- **Decision:** (a) Corrected `accept_invite` RPC (SECURITY DEFINER) — single transaction, writes `settings` not the nonexistent `expense_settings` (012:256); (b) platform-approval runs a service-role server action that CREATES the user (if new) + org + subscription in one transaction, superseding `approve_client_request`'s NULL-return (012:120-124).
- **Prevents:** partial joins; a dead approval path that "succeeds" without creating anything.

## 2026-08-03T19:11 — D — Audit log = one canonical implementation, write-only via RPC
- **Decision:** Audit writes go through a single SECURITY DEFINER logging RPC (insert-only, server-supplied actor); schema = migration 002 canonical shape (`org_id, user_id, action, entity_type, entity_id, old_value, new_value, ip_address, user_agent`); the divergent/dead `shared/lib/audit-logger.ts` is rewritten to this schema; SELECT narrowed to `can_admin_org`.
- **Prevents:** two divergent audit schemas, forgeable/unattributable rows, logs admins can't read.

## 2026-08-03T19:11 — D — Email via transactional provider + dev no-op
- **Decision:** Invite + new-user notification emails go through a mailer module behind a transactional provider (Resend); `DEV_EMAIL_*` envs default to a logged no-op; no provider keys in the repo.
- **Prevents:** "email sent" toasts with no email; hardcoded/committed secrets (resolves PRD OQ-4).

## 2026-08-03T19:11 — D — Org-wide defaults live on organizations table
- **Decision:** Migration 013 adds `default_currency` + `default_vat_rate` columns on `organizations` (org-wide source); per-(user, org) `settings` rows remain personal overrides; VAT applies to NEW entries only.
- **Prevents:** divergent org-default storage; retro-rewrites of historical VAT (FR-18).

## 2026-08-03T19:11 — D — Roster email via service-role lookup, not a new column
- **Decision:** Roster member emails resolved through service-role `auth.admin.listUsers` matching (the existing `emailLookup` pattern); no email column added to `profiles`.
- **Prevents:** duplicating `auth.users.email` under RLS (leak surface), schema churn for a read-only display field.
